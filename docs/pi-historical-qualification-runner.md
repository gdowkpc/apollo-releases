# Historical Pi qualification runner

On apollo-builder, run `node scripts/run_pi_historical_qualification.js TARGET.json FIXTURES.json OUTPUT_DIR`. Use a new private output directory for each run. TARGET contains the candidate build and runtime and installer objects, each with an absolute path and SHA-256. FIXTURES maps each predecessor record path to its exact artifact path and an absolute executable adapter path. The runner passes each adapter a request JSON and a private job directory. An adapter must restore the predecessor into a disposable environment, run its normal update route, and write result.json. Use scope isolated_transaction for namespace or synthetic runs. For full boot and receiver evidence, supply the existing gate's predecessor run object under run. Keep credentials and raw operator data out of logs. Only the unchanged release validator can admit full evidence. Missing fixtures and failed runs remain open.

The initial Build 422 inventory contains 218 entries. The retained Build 191 convergence archive is not an inventory row. Use the separate passing target-state workflow as compatibility evidence.
